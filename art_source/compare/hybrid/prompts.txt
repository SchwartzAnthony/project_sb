HYBRID SET: OpenAI paintings converted to pixel art by PixelLab (round AN comparison)

Tool: PixelLab MCP image_to_pixelart, faithful=true, init_image_strength=200,
no text prompt (it is a conversion, so the art bible lives in the OpenAI source).
Sources: art_source/compare/openai/<layer>.png

Source prep (src/make_src.py): cut-outs cropped to their visible area, scaled
to the OUTPUT size, quantized to 48 colours (PNG, transparency kept). Sent as
a data: URL. Note: much smaller than the planned 768 px. Bigger data URLs got
corrupted when copied into the tool call (PixelLab: "base64 did not decode"),
so the sources had to be small.

Problems
1. Transparency: PixelLab gave every cut-out back on a flat mid-grey
   background (about RGB 129,129,129), although the sources were transparent.
   The raw results are kept as <layer>_raw.png. src/fix_alpha.py put the
   alpha back by using the OpenAI cut-out's mask, scaled to the pixel size
   with hard edges.
2. bg: the painted sky/meadow does not compress well. Every data URL was
   >17k characters, and each copy into the tool call came out corrupted (3
   attempts, all rejected before generating, so no credits were used). So
   hybrid/bg.png is a STAND-IN and NOT PixelLab: the OpenAI bg run through
   tools/pixelate.py with compose.py's "paint" settings (960x540). To do it
   properly, PixelLab's upload endpoint (POST /v2/uploads -> upload:<id>) or
   an https URL to the image is needed.
3. The sign comes with the two people at the sides, because the OpenAI
   sign.png had them (faithful mode keeps what is there).

Compose
  compose.py hybrid pixel  -> title.png (= title_pixel.png)   KEPT
  compose.py hybrid paint  -> title_paint.png (for comparison; it smears the
                              black outlines and faces, much worse)
Pixel mode scales each layer by a whole number: hero x3, bg x2, the rest x1,
so the hero's pixels are 3x bigger than the crowd's.
